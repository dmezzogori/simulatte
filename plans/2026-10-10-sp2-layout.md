# SP2 Layout Implementation Plan

**Status:** draft for review, 2026-10-10. No product implementation has started. Resolve spec amendments A1–A3
and complete the agreed reviews before executing this plan. Execution method is not selected by this draft;
follow Davide's instruction when implementation is authorized. Checkboxes track future implementation only.

**Goal:** Ship the headless Layout subsystem in Simulatte 0.14 with deterministic placements/networks, tracked
physical inputs, staged construction, graph handles and portable trace metadata.

**Architecture:** Pure layout definitions and layer resolution feed an ordered preparation coordinator. The
coordinator generates one graph, validates references, binds existing components, then finalizes hashes before
SP1 activation. Python and TypeScript readers expose the stored layout without adding viewer behavior.

**Tech stack:** Python >=3.11, SimPy, existing MessagePack wire codec, standard-library geometry/JSON/hashlib;
pytest, existing TypeScript trace package and Vitest. No new runtime dependency.

**Spec:** [SP2 Layout design](../specs/2026-10-10-sp2-layout-design.md). The
[approved global design](../specs/2026-10-08-studio-global-design.md) and
[decision log](../specs/studio-decisions.md) remain authoritative until amendments are accepted.

## Global constraints

- Work on `feature/sp2-layout`, created from fetched `main` at `b1467709e88cf640155b83c037f06573fcddd875`.
- Python remains >=3.11; maintain CPython 3.11–3.15 and PyPy 3.11 compatibility. No web/frontend runtime additions.
- Full suite retains 99% branch coverage. Targeted tests use `--no-cov`; do not weaken the full gate.
- No-layout scripts preserve existing graph insertion order, event order, activation and dynamic construction.
- One Layout, one canonical resolved graph per environment; no directly passed graph mixed into that mode.
- Auto < code < file per leaf; lists replace; `{"$unset":true}` removes optional inherited values.
- Coordinates are finite float64 meters, z=0; speeds are meters per environment time unit. No implicit snapping.
- Physical reads reject auto values; include structural/negative dependencies; finalize only after all binding.
- Reuse the single pre-activation command queue. No layout work in event-emission or simulation hot paths.
- `layout.json` schema 1.0 and `layered-v1`, `network-v1`, `layout-hash-v1`; proposed trace extension 1.1/layout-v1.
- Preserve conventional commits, signed where available. If 1Password locks, `--no-gpg-sign` and report it.
- No implementation of viewer (SP3), interactive Studio/source snapshots (SP4), segment reservations unless A1
  is revised, or unrelated PyPy #59/packaging/branding fixes.

## Review focus

- A file override becomes physical only during binding: final D30 validation must still reject generated entity
  ids (Tasks 3, 7, 9).
- A formerly empty obstacle/connector set gains one member: saved-layer reuse must require a rerun (Tasks 3, 9).
- A stage constructs a component with a creation subscriber attached: its snapshot must be valid while its node
  remains unresolved, and observer count must not alter preparation (Tasks 7, 10).
- A recorder exists before layout resolution: HEADER must not capture provisional hashes; failed preparation
  must not create INITIAL (Task 9).
- A split lane has equal-coordinate aliases and overrides on the original segment: apply each parent override
  to the correct children without duplicate nodes or accidental reassignment (Tasks 5, 6).
