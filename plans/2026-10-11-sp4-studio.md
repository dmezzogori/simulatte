# SP4 Studio implementation plan

**Status:** approved by Davide on 2026-10-11; implementation and documentation prepared. Local gates pass; native Windows, actual Safari, remote CI and an unreproduced PyPy startup follow-up remain open.

**Goal:** ship local parameter/layout editing and reproducible fresh-process execution through `simulatte studio` and `simulatte run` in 0.16.

**Architecture:** a shared execution coordinator owns immutable snapshots, fenced attempts and a minimal SQLite run store. A trusted supervisor launches one-use execution children and transfers durable trace segments. The existing SP3 viewer gains live recording and editor adapters.

**Stack:** Python ≥3.11, SimPy, existing MessagePack, stdlib subprocess/sqlite3; optional Starlette/Uvicorn/websockets/watchfiles; existing React/Pixi/TypeScript workspace.

**Spec:** [SP4 design](../specs/2026-10-11-sp4-studio-design.md). Read it before executing a task; the signatures below are implementation boundaries, not permission to weaken its contracts.

Davide reviewed and approved the design and plan and instructed implementation. Execute inline, following repository testing/commit rules. No separate adversarial design-review evidence is claimed.

## Constraints

- SP5 owns experiments, replications, statistics, SSH and uv provisioning. One local execution slot in SP4; zero automatic retries; zero warm spares.
- Keep plain scripts/Runner/builders optional-decoration paths, read-only view and all SP3 exports.
- Core/run/worker have no web imports; server CPython, worker/core PyPy compatible.
- Trace 1.3 optional `execution-v1` only after A7 approval; readers retain 1.0–1.2. Layout stays 1.0.
- No model imports in coordinator/supervisor. Every inspection/run is a fresh child.
- Preserve 99% Python branch coverage, existing overhead gates and SP3 reader/export bounds.
- Protocol frame/envelope/fragment caps: 2 MiB/256 KiB/1 MiB; depth 64.
- Spool 256 MiB/1,024 files; segment 128 MiB; in-flight 16 MiB; recorder pending budget 64 MiB.
- Heartbeat 1 s/loss 5 s; stalled 10 s; cancel 2 s then TERM +1 s then KILL; full/no-ACK timeout 60 s.
- Writes/reuse/publication are revision- and attempt-fenced; no live result is committed before verification.
- Do not update version or publish as a side effect of implementing a task. Release preparation is Task 14 after acceptance.

## Review focus

| Risk often missed by happy-path tests | Owning tests |
| --- | --- |
| A dependency's editable finder or startup hook reloads working-tree code after ready | Task 3: custom finder, namespace/lazy imports, `.pth`/`.start`, cross-version venv fixtures |
| A descendant keeps a pipe open after the worker dies | Task 4: grandchild descriptor inheritance, guardian EOF, kill-on-close |
| A huge INITIAL/catalog/footer cannot fit a control message or spool reservation | Tasks 5–6: artifact reference, segmented transfer, oversize admission without deadlock |
| Returning to previous layout bytes bypasses revision conflict (ABA) | Tasks 8/11: monotonic revisions and two-tab undo/external-save conflicts |
| A late completed HTTP read applies an invalidated live trace to a new view | Tasks 9/12: delayed fetch, generation swap, cancellation and export pinning |

## Sequence and gates

Tasks 1–6 establish independently testable contracts; Task 7 connects the headless vertical slice. Tasks 8–12 add revision-aware Studio functionality. Task 13 is acceptance, Task 14 release documentation/packaging preparation. Each task adds neighboring tests for its new subsystem and uses targeted checks while developing; full checks run at integration gates.

Before each task: inspect current files/status and preserve unrelated changes. For each behavior, add the specified test, demonstrate the expected initial failure, implement, then run the stated checks. Commit only the task's files with the suggested conventional message after its checks pass. Line numbers are intentionally omitted because earlier tasks move code; paths and interface names are authoritative. Types introduced below are frozen dataclasses/enums in `execution/schema.py` unless assigned another file.
