# SP2 implementation handoff

SP2 Layout is implemented on `feature/sp2-layout`, targeting Simulatte 0.14.
The final product fix is `addf0fa1729077fa618305efcde496c116ae55f8`. Package metadata
remains 0.13.0; this branch has not been pushed, merged, tagged or released.

All ten implementation tasks passed independent task review. The final whole-branch
review found one Important and three Minor issues; all four were fixed and the
scoped re-review approved them with no remaining findings. See the complete
[implementation review](../reviews/2026-10-10-sp2-implementation-review.md).

The implementation covers placements, footprints and ports; deterministic auto-layout;
versioned code/file layers; lattice, lane and explicit networks; obstacles, clearance,
connectors and overrides; staged preparation and canonical intralogistics binding;
physical dependency tracking and three hashes; immutable trace 1.1 layout metadata;
and callback-free presentation re-resolution. The explicit-graph path is preserved.

existing skips. All eight unchanged no-subscriber benchmark gates passed on the

Post-fix 1k/10k-node preparation medians were 2.086558/22.152321 seconds; peak traced
allocation was 63,127,807/629,689,698 bytes. INITIAL payloads were 4,491,360/45,448,562
bytes, within the default 64 MiB limit. The report retains the earlier measurements
and explicitly shows the increased allocation. No new preparation budget was adopted.

Approved A1–A5 remain in force: node-only traffic, stale removed lane parents, trace
1.1 metadata, explicit manual-step activation/shared resource ownership, and canonical
AGV/static endpoint guards. The accepted PyPy recording limitation in #59 remains
unchanged: the local runtime differs from that historical CI runtime. Arbitrary-angle
equality observed locally is not a cross-platform guarantee. Hosted CPython lanes
not run locally are not claimed as verified.

SP3 viewer work, SP4 interactive Studio and source snapshots, segment reservations,
and release/version changes remain outside SP2. The reviewer considered inherited
extreme route-cost arithmetic but established no regression; this is an unconfirmed
future investigation topic, not an open SP2 defect.

## Implementation rulings

These implementation choices preserve the approved SP2 contracts. Each includes the cost of revisiting it.

1. Task1 includes a pure structural file-patch parser/validator next to schema definitions; task2 owns file I/O and semantic merge — task1 explicitly requires Python/schema acceptance parity before task2 exists. Cost if wrong: moving that validation helper without changing public behavior.

2. Use existing feature/sp2-layout checkout as requested rather than creating another worktree — initial request selected this repository/branch and all docs/agent context use it. Cost if wrong: later relocation, no loss of original changes (baseline clean).

3. unset permitted structurally on patchable required/defaulted values, rejected semantically only where resolved model requires; complete code constructors reject sentinel recursively. This follows spec8.1; cost if wrong: constructor/schema validation rework before public release.

4. M1 uniqueItems numeric-equality divergence is a Task1 shared-schema-acceptance gap and joins the numeric fix — Task1 explicitly promises parity for overlapping constraints. Cost if wrong: a small additional validator/test change.

5. Explicit effective directed arc records default forward; both applies to authored lattice/lane/connector segments — spec6.5 directed adjacency preservation overrides generic8.2 default example. Cost if wrong: default interpretation change; choosing both would fabricate reverse paths now. Clarify spec at next serial docs point.

6. complete connector address values may replace atomically because nodeAddress schema requires complete identities; ordinary partial maps keep per-leaf merge. Cost if wrong: broaden future partial address API; no currently valid partial-address patch is lost.

7. network-owned selection dependencies may extend candidate membership/negative predicates for post-barrier nonmatching targets before finalization; never change existing selected values, regenerate graph, or refresh user-stage/binder collection reads. This reconciles spec9.2 allowed presentation-only additions with8.2 final candidate closure. Cost if wrong: dependency descriptor/preparation rework; final reuse remains conservatively safe because new obstacle/connector flags are tracked. Descriptor origin distinguishes this narrow internal extension.

8. the runtime resolved graph contains enabled canonical nodes/traversals only; disabled definitions remain in ResolvedNetwork definitions/address metadata for diagnostics and override replay — this gives enabled-graph validation its direct meaning and prevents traffic allocation/binding to disabled nodes. Cost if wrong: graph membership/metadata API adjustment before release; no existing no-layout behavior changes.

9. per-node effective capacity travels in immutable ResolvedNetwork.capacities, keyed by canonical identity/id with an explicit documented interface, rather than adding a speculative public LayoutGraph metadata API. Task7 consumes it at manager binding; graph factory validates structure only, geometry/overrides stay Task6. Cost if wrong: add a read-only graph metadata accessor later without changing capacity semantics.

10. override unset never resets schema defaults. Preserve tombstones through ordered application; optional capacity/speed_limit remove to None, final unset of required enabled/direction errors when applicable resolved graph input is consumed. Later override may repair tombstone; unmatched stale records remain warnings. Follows spec8.1 and Task2 semantics. Cost if wrong: adjust final property-requiredness before release, no silent reinterpretation of author intent.

11. custom traffic ownership registration gets explicit named binder linkage (Layout.register_resource_owner(manager, owner=identitytoken, graph=GraphRef, binder=name)); verify that named on_bind exists beforeprepare rather than guessing internals or accepting unrelated binder. Owneridentity is runtime-only, never serialized as pointer/repr. Follows approved custom-manager ownership/binder contract; cost if wrong is prerelease API spelling adjustment.

12. builder may install compatible defaults beneath a partial file network patch lacking generator type, but never replace a prior authored code network (even if file tombstone makes effective type/network absent), nor override a complete file network. Invalid/unset declarednetwork remains error; caller rolemapping needed for existingnetwork. Follows code<file and no-overwrite contracts; cost if wrong is stricter builder declaration detection prerelease. FreeTrafficManager defaults remain stateless/no sharedresource registration needed.

13. Model-facing physical values use canonical schema numeric normalization and recursively sorted mapping keys, including parent/default/finalized reads, while lists preserve authored order — callbacks must consume the same equivalence class that approved hashes/reuse compare; numeric part already §§4/8.3, map iteration spelling made explicit. Cost if wrong: prerelease physical-map API adjustment; retaining authored map iteration would instead require changing approved identity semantics.
