U1 — major — Backpressure can prevent activation from supplying the writer’s prerequisites.
Spec §§9.3, 10, 11.1–11.2; Task 9. T6 remains partial.

The header contains the requested manifest, finalized at activation, while preactivation events
must be retained in a single PRELUDE record. Model construction can fill the pending-byte budget
before reaching activation.

Failure scenario: attach a recorder, construct enough entities to exceed the buffer limit, then
configure warm-up and activate. Blocking construction prevents the writer from obtaining the final
header/prelude data. Exempting prelude buffering instead permits unbounded memory; writing the
header early can record stale warm-up. A sufficiently large single prelude also exceeds the
reader’s record limit.

Fix: define bounded preactivation storage/publication explicitly—for example, temporary spooling
with multiple bounded prelude records, or activation-dependent manifest fields in a later record.
Test construction exceeding the buffer limit, subsequent warm-up configuration, activation and
readable completion.

U2 — major — A batch larger than the backlog limit cannot ever be admitted.
Spec §§6.2, 11.2; Task 9. T6 remains partial.

The strict pending-byte bound has no oversized-batch rule.

Failure scenario: max_pending_bytes=1024, one-event chunks, and an ordinary 2 KiB event. Even an
empty queue cannot accommodate it. Waiting never resolves the condition; admitting it violates the
required bound. Non-debug oversized events must also remain recordable.

Fix: define an explicit oversized-batch admission policy consistent with D54, such as admitting one
oversized batch only when otherwise drained, with a documented effective memory bound. Test this
independently of ordinary saturation. Also remove §18’s obsolete promise that simulation never
waits for I/O except during close.

U3 — major — The intralogistics steps still omit prerequisites for their green checks.
Tasks 14–17.

Two concrete ordering problems remain:

• Task 14 introduces reserved-ID rejection, but the existing builder (src/simulatte/intralogistics/
  builders.py:121) explicitly supplies agv-0, agv-1, etc. Its existing builder tests then fail. The
  builder is only explicitly scheduled for modification in Task 17.

• Task 15 requests replay-equals-live checks during fleet missions, but warehouse inventory and
  traffic reservations already mutate during those missions; their events arrive in Task 16. A
  full-registry comparison therefore fails.

Fix: include intralogistics builder ID/prefix migration in Task 14. Explicitly scope Task 15’s
comparisons to implemented state, and place the full-registry intermediate-cursor check after Task
16.

U4 — minor — touches still needs lifecycle-operation semantics.
Spec §6.1; Tasks 2–3. T10 remains partial.

The restored declaration permits fixed (kind, field) targets, but generic entity.created and
entity.retired operate on whole entities, including kinds registered later. Neither lifecycle
permissions nor touches=None semantics resolve this.

Failure scenario: debug validation rejects legitimate creation or retirement of a newly registered
custom kind—or an implementation broadly bypasses validation to accommodate it.

Fix: explicitly separate lifecycle validation from field mutations: validate creation against the
selected kind’s schema and retirement against the addressed entity, with documented permissions.
Add a debug-mode create/retire test for a dynamically registered kind.
