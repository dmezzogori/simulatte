# SP1 review 2 (Astra, Codex GPT-6-Astra xhigh)

- **Date:** 2026-10-08
- **Reviewed commit:** d929801
- **Verbatim findings below; triage at the end.**

T1 — blocker — The grant hook still precedes the complete transition (S1).
Spec §6.3; Task 6.

SimPy removes a granted request from put_queue after _do_put returns. Emitting job.granted inside
_do_put therefore removes it from replay while it remains in the live queue. An immediate grant
also produces queue_length=1 at the specified insertion boundary, contradicting Task 6’s expected
zero.

Fix: emit after both queue removal and user insertion are complete. Define which phase queue_length
measures and align its test. Also remove the assumption that a newcomer already has its final
position: sort_queue() subsequently refreshes priorities.

T2 — major — Cancellation bypasses the resource hooks (S1).
Spec §6.3; Task 6.

A waiting request’s cancel() removes it directly from the queue without invoking the proposed
hooks. An interrupted waiting process therefore leaves a ghost queue entry in replay. Conversely,
SimPy permits releasing an ungranted or already-released request; unconditional users.remove would
remove something absent.

Fix: instrument successful waiting-request cancellation and emit release deltas only for actual
membership changes. Test interrupted waits and duplicate releases. This concerns the existing
PriorityResource, without assuming preemption support.

T3 — major — Initializers can still defer work past the snapshot (S10).
Spec §10; Task 5.

An initializer can create an ordinary event, append a state-mutating callback, and call
event.succeed(). Neither process() nor timeout() is involved, and time remains unchanged, but the
callback executes after initial-state capture. Even allowed resource requests carry deferred SimPy
callbacks.

Fix: enforce the scheduling boundary itself, with narrowly specified exceptions for internal
resource initialization. Add a succeeded-event callback test; the current two guards cannot
establish the promised guarantee.

T4 — major — Pending-order deltas still precede their mutations (S6).
Spec §6.4; Tasks 15–16.

The catalog attaches pending-list removal to order.status_changed. However, _check_pending_queue()
calls _dispatch(), which changes order and AGV state, before removing dispatched orders from
_pending_queue later. Replay removes membership too early; delaying the status event makes
intervening AGV events inconsistent instead.

Fix: emit membership changes at their actual mutation points, or explicitly refactor dispatch into
a coherent transition while preserving hook semantics. Test pending redispatch and interruption/
requeue at intermediate cursors.

T5 — major — Ownership fields lack an assignment lifecycle (S18).
Spec §§5.2, 6.4, 12.1; Tasks 7, 14, 20–22.

Adding job.shopfloor and agv.fleet does not establish when ownership becomes known. Jobs currently
exist before ShopFloor.add(); AGVs exist before their coordinator. Neither psp.entered nor
shopfloor.entered specifies an ownership delta.

A job constructed after activation and subsequently added to a shop can consequently retain an
unknown owner in replay, breaking ownership-based filtering.

Fix: define nullable unowned states, assignment points, ownership deltas and reassignment rules.
Test creation followed by attachment after activation, not only systems fully constructed before
the initial snapshot.

T6 — major — The writer has no bounded backlog policy (S13).
Spec §§11.2, 18; Task 9.

The writer thread closes chunks, while the simulation supposedly never waits for I/O except at
close(). If production outpaces compression or storage, either the open buffer exceeds its limits
or pending buffers accumulate indefinitely. Chunk limits do not bound backlog; this conflicts with
global C1.7’s bounded-memory target.

Fix: bound pending bytes and define backpressure or explicit recording failure. Specify producer-
side sealing when necessary. Test a deliberately slow writer on CPython and PyPy.

T7 — major — Successful close and background failure are undefined (S13).
Spec §11.2; Task 9.

The spec says close() writes scalars and the footer, without requiring pending publication to
finish first. Closing while a chunk is being written could place the footer before its committing
index. A serialization or disk-write exception in the thread also has no specified route back to
the caller.

Fix: require one ordered publication path and a close barrier: all accepted records and indexes
precede the footer; successful close means publication completed. Latch and propagate background
failures. Test write failure, close during publication and repeated close.

T8 — major — Escaping still excludes valid browser-hostile keys (S16).
Spec §9.1; Tasks 1, 11.

Escaping __proto__ and leading ~ is insufficient: the selected decoder also rejects constructor and
prototype. Python can therefore write a valid payload such as {"constructor": 1} that TypeScript
cannot decode. See the upstream decoder guard (https://github.com/msgpack/msgpack-javascript/blob/
main/src/Decoder.ts#L619-L622).

Fix: escape the complete reserved set, test collisions and nested occurrences, and reconstruct
unescaped maps safely—including an own __proto__ property.

T9 — major — Listener registration now ambiguously activates projection early.
Spec §10; Task 5.

Task 5 says on_initial_state() “also sets _projection_active”; the previous plan explicitly enabled
it only after initial-state notification. Following the revised interface literally, attaching a
recorder before constructing entities assigns ordinals to prelude events, contradicting the
activation boundary and first-domain-ordinal-zero contract.

Fix: distinguish requesting projection from activating it. Restore the explicit activation sequence
and test that prelude ordinals remain absent and the first post-snapshot domain ordinal is zero.

T10 — major — The rewritten decorator drops required catalog metadata.
Global C1.2; SP1 §6.1; Task 2.

The previous event_type(..., touches=...) interface declared which state fields an event’s deltas
could affect. Revision 2 replaces it with presentation=... and provides no replacement for touches,
although the global contract still requires that information.

For a custom event, readers and validators now lack its declared delta targets.

Fix: retain both declarations, serialize them into catalog entries/extensions, and test their round
trip and validation.

T11 — major — Task 4 now depends on Tasks 6 and 7 (S22).
Tasks 4, 6, 7.

Task 4 makes Router an entity with shopfloor state and service streams containing server IDs.
Server and ShopFloor acquire those IDs only in Tasks 6 and 7. Building a normal system at Task 4
therefore cannot satisfy both the specified interfaces and its green tests/core checkpoint.

Fix: move minimal Server/ShopFloor identity attachment earlier, or split binding infrastructure
from Router integration and perform integration after its identity dependencies exist.

T12 — major — Correct workload accounting conflicts with exact legacy parity (S19).
Spec §12.3; Task 21.

The completion-based fix is correct, but “series identical” is unattainable for the specified
yielding-hook case. A read-only probe produced legacy samples [(0,5), (5,0), (6,8)]: five units
finish at time 5, remain held by an after-hook, and a three-unit job arrives at time 6. The old
collector re-counts completed work; the new result should be 3.

Fix: document this intentional correction and use an independently specified expected series for
this case. Preserve parity elsewhere, with an explicit floating-point comparison policy.

T13 — minor — Default-generated seeds can still invalidate regenerated fixtures (S23).
Spec §11.4; Task 11.

Fixture generation fixes volatile metadata, provenance and chunk boundaries, but includes default-
generated seeds. Those seeds come from os.urandom and remain part of canonical manifest content. If
included in regenerated fixtures, comparison still changes every run.

Fix: pin entropy during generation, or reserve default-seed coverage for frozen fixtures/separate
tests and use explicit seeds for regenerated fixtures.

T14 — minor — The replacement benchmark omits its promised RNG measurement (S20).
Spec §14; Tasks 12, 25.

The pre-generated feeder correctly equalizes simulation work, but bypasses Router sampling and
stream binding. The spec promises a separate RNG benchmark; neither benchmark task assigns one. A
substantial sampling regression could escape the reported measurements.

Fix: add an explicit binding/sampling benchmark with controlled draw counts and CPython/PyPy
results, separate from the matched-workload overhead comparison.

T15 — minor — The reader’s manifest must explicitly merge both parts (S14).
Spec §§9.3, 11.3; Tasks 8, 10.

Section 9.3 stores requested fields only in the header and final fields only in the footer, while
§11.3 describes Trace.manifest as “final if the footer exists.” Read literally, completing a trace
removes seed, versions and parameters from its public manifest.

Fix: specify that Trace.manifest always returns the merged view, with finalization status reported
separately. Test that requested fields remain available after close alongside the final stopping
policy.
