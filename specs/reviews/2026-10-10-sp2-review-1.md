> # SP2 Layout spec/plan — adversarial review 1
>
> Scope: `specs/2026-10-10-sp2-layout-design.md` (spec) and `plans/2026-10-10-sp2-layout.md` (plan) at `096c6d5`, against global §4/C2/C1.10/§11 and the decision log. >
> ## Blocking (spec-level; must be corrected before implementation)
>
> **1. Leaf freeze granularity is ambiguous and breaks the closure — High.** Spec §9.1 (lines 408-411) lets stages "declare new placement leaves" but not "rewrite earlier frozen leaves"; §9.2 step 2 (431-433) freezes "each stage's outputs"; §8.1 (323-324) says a later stage cannot overwrite a frozen property. Counterexample: stage 0 places `hall` with position only; stage `machines` reads `hall.rotation` with `default=0` (absence dependency recorded, §8.2 line 346), then calls `place("hall", rotation=90)` — a "new leaf". Final resolved rotation is 90 (or the file's value), geometry and obstacles use 90, but the closure says "absent→0", and `reresolve_presentation` compares a recorded absence against a saved layer that now holds 90. Fix: a target's placement freezes entirely (all leaves, including absences) at the end of the stage that declared the target; later stages may only place targets they themselves attach/declare; file precedence for a target is applied exactly once at its freeze. State whether a code value declared after the target's freeze is an error or ignored.
>
> **2. Node binding reads the public AGV getter that the spec makes raise — High.** `src/simulatte/intralogistics/graph.py:52-56` builds `NodeBinding.agvs` by calling `getattr(entity, "current_node", None)` on every live AGV. Spec §10 (488-490) requires the public `current_node` to raise `LayoutNotReady` while unbound, and §9.2 step 5 (444-446) binds nodes *before* resolving component endpoint handles. In layout mode every AGV is unbound at that moment, so binding either raises or (if implemented to return None) produces empty `agvs` lists that are then filled by endpoint resolution in an unspecified order. `agvs` is a semantic field in the initial state (`agv.py:178-197`, digest covers the initial state), so the §13 "equivalent trajectories" test between layout and explicit modes can fail on initial-state ordering. The plan's Task 7 file list (plan lines 216-218) omits `graph.py`. Fix: `NodeBinding.__init__` reads the private nullable field; endpoint resolution runs in attachment order; add `graph.py` to Task 7.
>
> **3. Approach-point definition is numerically unstable — High.** §6.4 (226-230): the approach point is "the first point strictly outside the owner's inflated rectangle; choose the next representable float outward at the boundary", and the approach→network segment "has no exemptions"; §6.1 (180) makes touching the inflated boundary blocked. `nextafter` per coordinate does not keep a 2-D point on the ray, and the outer segment then starts at distance clearance+1 ulp from the owner: a float distance evaluation (rotated rectangle, 30°, `hypot`/dot products) can round to ≤ clearance and report the owner's own connector as blocked by the owner. Fix: an explicit positive approach margin (a named physical input with a default, e.g. 0.01 m) and/or make the owner check of the outer segment exclude its start point. Pair with finding 6 (exact predicates).
>
> **4. Network absence is not a recorded negative dependency — Medium-High.** §8.2 (338-342) records what "network generation reads"; nothing is recorded when no network is declared. Counterexample: production-only run (no network, no GraphRef); saved layers reused with a file patch adding `network: {type: lattice, ...}` (allowed by §8.1 line 315). No recorded query is touched, so `reresolve_presentation` reports presentation-only; a real re-run generates a graph at the barrier ("after all stages if none does", §6 line 167), which is physical under C2.6. Fix: record the network variant including `none` and grid presence as structural dependencies, or define that a network with no consumer is not generated — the spec must pick one.
>
> **5. Placeable kinds and default footprints are undefined — Medium.** §4 line 120 gives a 1×1×0 footprint only to "unknown custom entity kinds"; §5 step 4 sizes every cell from "the maximum rotated XY footprint among placeables"; C1.1 lists placeable kinds (servers, PSPs, warehouses, stations, parking, AGVs, nodes) and leaves out `shopfloor`, `router`, `fleet`. Without a per-kind table the auto layer and `full_hash` are implementation-defined. Fix: a normative table of placeable kinds and default footprints in §4; state that non-placeable kinds are excluded from auto-layout.
>
> ## Nonblocking
>
> 6. **Platform/runtime-dependent geometry decisions** (§6.1 180-183 mandates exact rationals only for lane intersections). `math.hypot` differs between CPython and PyPy implementations at the ulp level; rotation uses libm `sin/cos`. Blocked/free, nearest-target and tie decisions can flip, so the same inputs give different physical hashes per runtime; plan Task 10's CPython/PyPy hash comparison would be flaky. Recommend: all predicates and selections in exact rational arithmetic (`Fraction` from float64, squared distances), exact cos/sin for multiples of 90°, floats only for stored outputs via correctly rounded conversion; document residual platform dependence for other angles.
> 7. **Snap formula is not "nearest"** (§4 128-129, plan Task 1 line 97): `floor(q + 0.5)` for `q = 0.49999999999999994` yields 1 because `q + 0.5` rounds to 1.0. Use `f = floor(q); f + (q - f >= 0.5)`.
> 8. **Builder layout mode under-specified** (§10 506-513): the five "documented role names" for `nodes=` are not listed anywhere; one network per layout means two prefixed systems cannot each own a line as today — the caller must build a union `Explicit` graph first; layout-mode AGV ids `<prefix>vehicle-i` differ from no-layout `<prefix>agv-i` (`builders.py:128`), which complicates the §13 equal-ids equivalence test. Enumerate role names; keep `f"{prefix}agv-{i}"` when a prefix is given.
> 9. **Explicit networks have no owner exemption** (§6.1 185-187): a bay node inside an `obstacle=True` warehouse is invalid; builder layout mode must never mark warehouses as obstacles. Document or add a per-node owner exemption.
> 10. **Post-finalization construction unspecified** (§9.2 466-469): say that constructor refs of components created after finalization/activation resolve immediately against the frozen graph (precedent: `tests/intralogistics/test_activation.py:113-122`), and how the one-resource-manager rule applies then.
> 11. **Wording/API table gaps:** §5 line 139 "exactly once after every stage" vs C2.4 "after the last stage"; "component-id order" (151) undefined; `node_at`, `require_path`, `load`, `save`, `to_dict/from_dict`, `on_bind`, `stage` are used but absent from the §4 table (92-108); `Layout.port(entity_id: str, …)` takes a string while `place` takes `Entity | str`. Cell size coupling (step 4): editing one explicit rotation moves every auto-positioned entity — consider sizing from auto-positioned entities only.
> 12. **Plan interface gaps:** Task 2 `resolve_layers(code_stages, file_layer, auto_layer)` (plan 114) but the auto layer exists only after all stages (Task 4) while Task 3 freezes stages without it — specify the `auto_layer=None` pass and the final pass. Task 7 omits `graph.py` (finding 2). Task 9's INITIAL size check should name the bound: `ReaderLimits.max_record` = 64 MiB (`reader.py:68`); Task 10 should measure INITIAL bundle size for the 1k/10k layouts, not only preparation time.
> 13. **Generated node ids vs reserved names:** `_check_name` (`entities.py:335`) rejects `<kind>-<digits>` for kinds registered *at attach time*; a later-registered kind named like an address tag would retroactively reserve ids such as `lattice-3`. Make the encoding never end in `-<digits>`.
> 14. **Unacknowledged contract changes to list in Task 0:** (a) `env.step()` raising with an unprepared layout — new core behavior beyond C1.10; (b) a recorder created after `Layout.prepare()` misses prelude events (`writer.py:231-233` subscribes at construction) — state that the recorder must attach before `prepare()` to capture the prelude; (c) one `ResourceBasedTrafficManager` per layout graph (§7 285-288) is a new rule, allowed today in explicit mode; (d) `ACTIVATION_MANIFEST_FIELDS` gains `layout` (writer.py:62), which is an SP1 trace-contract edit beyond A3's wording.
> 15. **Package import cost:** exporting `Layout` from `simulatte/__init__.py` will import `intralogistics.graph` at package import; keep it lazy as `entities.py:375` does. The import audit (`test_import_audit.py:8-14`) only constrains the intralogistics→core direction, so no violation.
