# SP1 review 1 (Astra, Codex GPT-6-Astra xhigh)

- **Date:** 2026-10-08
- **Reviewed commit:** ef4dea2 (spec cd888e2, plan ef4dea2)
- **Verbatim findings below; triage at the end.**

S1 — blocker — Server events are emitted at the wrong resource boundaries.
Sections: Spec §6.2–6.3; Tasks 6–7.

Problem/scenario: SimPy can grant a request inside ServerPriorityRequest construction, before
Server.request() returns. The proposed job.granted occurs later, when ShopFloor.main resumes—and
never occurs for direct Server users. Queue reordering also happens inside construction, before the
proposed insertion event: a reorder can therefore move a job that replay has not inserted yet. An
in-memory probe confirmed both orderings.

Fix: Instrument authoritative insertion, grant and removal transitions in Server. Test replay
against live state at intermediate cursors, including direct resource use and immediate grants.
Insert newcomers at their final position; do not emit moves for every sibling whose index merely
shifted.

S2 — major — Entity creation has two owners.
Sections: Spec §5.1, §6.3; Tasks 3, 6–7, 14.

Problem/scenario: Registry attachment emits entity.created with a create delta, while job.created
and order.created also carry create. Runtime creation therefore creates the same entity twice. Task
3 requires generic creation, but Task 7’s expected sequence includes only specialized creation.

Fix: Choose one owner for the creation delta. Specialized events can add metadata without
recreating the entity, or attachment can emit the specialized creation event. Test creation after
activation.

S3 — major — Retirement is implemented as an API but never assigned to built-in lifecycles.
Sections: Spec §5.1, §6.3; Tasks 3, 7, 14–15.

Problem/scenario: Nothing specifies when finished jobs or completed, cancelled and failed orders
call retire(). Implementing the listed events literally leaves every completed entity in the live
registry and subsequent snapshots. Repeated snapshots then grow with historical throughput,
undermining the size and memory targets.

Fix: Define terminal retirement points, including recoverable versus terminal failures, after
required completion notifications and reference cleanup. Test that live-registry membership falls
while Python history remains available.

S4 — major — Active motion cannot survive seeking.
Sections: Spec §5.2, §6.3–6.4, §11; Tasks 14–15.

Problem/scenario: AGV state has no active-motion field, and agv.move_started explicitly has no
deltas. Seeking into a later chunk during a long movement loses the start event and therefore the
motion plan. Node state also omits the existing coordinates needed to resolve endpoint IDs. This
violates global C1.2.

Fix: Add active motion to replay state, with start, completion and interruption updates. Serialize
node geometry. Test seeking across a chunk boundary while movement remains active.

S5 — major — Node state conflates definitions, occupancy and reservations.
Sections: Spec §5.2, §6.3; Task 14.

Problem/scenario: A scalar occupant cannot represent existing node_capacity=2 behavior or multiple
AGVs sharing a node under free traffic. Moreover, the next node is reserved before travel finishes,
while proposed occupancy updates occur at movement end. Directly attaching frozen, environment-free
Node definitions also leaves ownership unclear when graphs are reused.

Fix: Introduce environment-local node bindings; distinguish location membership from traffic
reservations and represent both with appropriate collections. Make repeated attachment of the same
definition within an environment well-defined.

S6 — major — The intralogistics catalog does not cover its declared state.
Sections: Spec §5.2, §6.3; Task 15.

Problem/scenario: Order timestamps, AGV unassignment and charging swap_pool changes lack
corresponding deltas. Replay can retain an assigned order after mission cleanup or a full battery
pool after a swap. Instrumenting FleetCoordinator._transition_agv alone also misses public
AGV.transition_to() calls used by existing tests.

Fix: Map every declared state field to all its mutation sites, including interruption and cleanup.
Split Task 15 into reviewable resource/fleet changes with intermediate-state replay tests; a
successful final snapshot comparison alone is insufficient.

S7 — major — The semantic projection includes presentation data.
Sections: Spec §6.3, §9.1; Task 8.

Problem/scenario: entity.created includes label, but project_event hashes the complete payload and
deltas. Changing only a runtime-created entity’s display label changes its semantic digest,
contrary to global C1.6.

Fix: Specify semantic projection rules for payload and state fields, including lifecycle metadata.
Test that label changes alter the full trace but preserve the digest.

S8 — major — The plan does not enforce observer-origin event classification.
Sections: Spec §6.1, §7.1; Task 2.

Problem/scenario: The spec says subscriber-emitted events are observer events, but the planned
emitter stamps whatever event instance it receives. A subscriber can emit a DomainEvent, receive an
ordinal and inject deltas into the recorded trajectory. Scheduling/RNG checks do not catch this.

Fix: Reject domain-event emission during subscriber delivery, and enforce empty deltas on observer
events. Test this separately from FIFO delivery.

S9 — major — The guard pattern alone does not establish observer purity.
Sections: Spec §6.3, §7.1, §13; Tasks 6, 22.

Problem/scenario: Moving today’s job.priority(self) evaluation inside if env.wants(...) removes
eager work but makes the extra policy invocation depend on recording. A stateful or random custom
priority policy can then change scheduling when tracing is enabled. The spec does not require
payload construction to use already-computed values.

Fix: Require event payloads to use captured transition data, such as the priority already computed
for the request. Add a counting/stateful-policy invariance test; pure built-in policies will not
expose this mistake.

S10 — major — Initializer validation allows unfinished initialization to escape past the snapshot.
Sections: Spec §10; Task 5.

Problem/scenario: An initializer can call env.process(helper()) and return. Initially this
schedules only a zero-time initialization event, so the proposed checks pass. The initial snapshot
is captured before helper runs, even if it subsequently changes initialization state or yields a
positive timeout.

Fix: Prohibit deferred state-changing initialization, or provide a controlled mechanism that
completes it before the initial-state boundary. Test nested process creation, not just direct
timeout(1).

S11 — major — The sampler interfaces do not cover actual callback shapes.
Sections: Spec §8.2; Tasks 4, 7, 16.

Problem/scenario: Routing factories now return RNG-taking functions, while as_sampler accepts zero-
argument scalar callables. Task 7 nevertheless assigns routing binding to it. Deterministic flow-
shop routing and legacy custom routes have another signature. Charging callbacks currently take
(current_level, target_level), which the proposed scalar helper also cannot preserve directly.

Fix: Define explicit binding protocols for routing and contextual duration functions, alongside
scalar distributions. Test all three shop types, legacy custom routing, shared descriptions and
existing charging/warehouse callback signatures.

S12 — major — Default seeds exceed the wire integer range.
Sections: Spec §4, §9.3; Plan constraints and Tasks 1, 4, 8.

Problem/scenario: seed=None produces an unsigned 64-bit integer, but the wire contract permits only
±(2⁵³−1). Almost every automatically generated seed therefore either fails manifest encoding or
loses precision in JavaScript.

Fix: Define a lossless seed representation in manifests, such as a canonical decimal string, or
restrict generated and accepted seeds consistently. Test default-generated seeds through Python and
TypeScript decoding.

S13 — major — The synchronous recorder violates the publication-latency contract.
Sections: Spec §11.1–11.2; Task 9; global C1.7.

Problem/scenario: Wall-clock age is checked only when another event arrives, and writing explicitly
uses no independent thread/process. After one completed event, a model callback can compute for
minutes, leaving that event unpublished far beyond the one-second limit. Advancing a mocked clock
before another emission does not test this case.

Fix: Publish immutable completed buffers independently of simulation progress. Add a test where no
further event arrives before the publication deadline.

S14 — major — The header manifest cannot represent the promised continuing run.
Sections: Spec §9.3, §11.1; Plan review focus and Tasks 8–10.

Problem/scenario: The manifest lives in the header, but the stopping policy is learned from run()
and “last call wins.” After run(until=10); run(until=20), the in-memory manifest can say 20 while
the already-written header says 10—or predates either value. The footer has no final manifest.

Fix: Define authoritative metadata finalization: separate initial/requested metadata from final
stopping metadata, and give readers a specified way to obtain the latter. Test the reopened trace’s
manifest after multiple runs.

S15 — major — The TypeScript API is synchronous but its decompressor is asynchronous.
Sections: Spec §11.3; Task 11.

Problem/scenario: openTrace(bytes): Trace and stateAt(...): Record provide no asynchronous
preparation step. DecompressionStream produces a stream consumed asynchronously, so the first call
needing an undecompressed chunk cannot satisfy those signatures. WHATWG Compression Standard
(https://compression.spec.whatwg.org/#dom-decompressionstream)

Fix: Make opening/seeking asynchronous or introduce asynchronous preparation followed by
synchronous access to prepared state. This also matches the global viewer contract.

S16 — major — Legal Python map keys can fail JavaScript decoding.
Sections: Spec §9.1, §11.3; Tasks 1, 3, 11.

Problem/scenario: Arbitrary string map keys are allowed, including an entity named __proto__. The
selected JavaScript MessagePack decoder rejects that key. A valid Python snapshot can therefore be
unreadable by the browser. Decoder implementation (https://github.com/msgpack/msgpack-javascript/
blob/main/src/Decoder.ts)

Fix: Define reversible key escaping or another safe wire-map representation, with matching Python/
TypeScript behavior. Add hostile-key fixtures. Restricting names alone would not fix custom payload
maps.

S17 — major — Reader recovery and allocation limits are insufficiently specified.
Sections: Spec §11.1; Tasks 9–11.

Problem/scenario: The spec tolerates damaged trailing writes, but Task 9 stops at any bad CRC and
labels the file truncated. Interior corruption can thus masquerade as an ordinary partial run.
Separately, valid compressed input can expand far beyond writer chunk targets, which do not
constrain imported files.

Fix: Distinguish committed-record corruption from incomplete tails; enforce record, decompressed-
output, collection and nesting limits, plus index/footer bounds. Test that a complete CHUNK without
its committing INDEX remains invisible. Include the global oversized-event policy in writer
acceptance tests.

S18 — major — Collectors lack ownership and result namespaces.
Sections: Spec §12; Tasks 19–21.

Problem/scenario: EMACollector(alpha) attaches to an environment, but no owner filter is specified.
Two prefixed shop floors can therefore each collect both floors’ jobs. Fingerprints then merge
scalar dictionaries keyed only by KPI name, overwriting identically named results. Fleet collectors
have the same problem.

Fix: Define collector scope explicitly and propagate sufficient ownership information through
events. Namespace scalar results by scope and KPI identity. Test two independent systems sharing
one environment.

S19 — major — The workload collector migration changes its meaning.
Sections: Spec §12.3; Task 20.

Problem/scenario: Replacing the existing completion-time skip logic with job.released delays
subtraction until resource release. An after-operation generator hook can hold the server for ten
additional time units after processing completes. The new series then reports completed processing
as remaining work, violating both existing semantics and the promised parity.

Fix: Update remaining processing work at operation.completed, using operation identity and
processing data. Keep resource occupancy accounting separate. Add a parity case with a yielding
after-operation hook.

S20 — major — The benchmark does not compare equivalent work across versions.
Sections: Spec §14; Task 12.

Problem/scenario: Feature-detecting seeding does not preserve the workload. Global RNG draws and
independently hashed streams produce different arrivals, routes, service times and queue lengths
for the same numeric seed. Congested models can consequently show more than 3% timing differences
unrelated to instrumentation.

Fix: Use identical pre-generated workload inputs for the overhead comparison, with matching job/
operation counts and observation settings. Benchmark RNG implementation changes separately. Control
PyPy warm-up and report timing variability as well as medians.

S21 — major — G3 measures modes whose implementations arrive only in G4.
Sections: Spec §2, §14; Tasks 12, 18–21.

Problem/scenario: G3 fixes logging and KPI budgets before the bus logger, KPI framework and
replacement collectors exist. Its “KPI” mode can measure a digest with no final bus collectors,
while logging still uses the legacy implementation. These results cannot validate the advertised
modes.

Fix: Include a representative bus sink and KPI collector in the vertical slice, or explicitly defer
acceptance of those budgets until their implementations exist. Ensure the no-subscriber
configuration is actually available and empty.

S22 — major — Several task boundaries cannot satisfy their stated green-suite checkpoints.
Sections: Tasks 4, 6–7, 20, 23.

Problem/scenario: Task 4 removes distribution __call__ before Task 7 migrates Router’s calls. Task
6 removes Server._idx while ShopFloor.main still reads it (src/simulatte/shopfloor.py:1037),
producing an immediate failure before Task 7. Executable gallery examples also require migration
alongside affected APIs, not merely eventual documentation updates.

Fix: Move coupled producer/consumer changes into the same task, or retain temporary internal
bridges until the consuming task lands. Include affected examples and their byte-identical
documentation blocks at each breaking boundary.

S23 — minor — Byte-for-byte fixture regeneration is nondeterministic.
Sections: Spec §9.3, §11.1; Task 11.

Problem/scenario: Fixtures contain volatile metadata and runtime/dependency provenance, and chunk
boundaries can depend on wall-clock timing. Regeneration across CI runtimes—or simply at another
time—can change bytes without a format regression.

Fix: Use controlled fixture metadata and deterministic chunk limits, or compare normalized
canonical content. Keep separate fixed binary fixtures for decoder compatibility.

S24 — minor — The hand-computed KPI oracle is wrong.
Section: Task 19.

Problem/scenario: For value 2 on [0,5) and 4 on [5,10), the integral over [3,10) is 2×2 + 4×5 = 24;
the mean is 24/7, not 22/7. A correct implementation would fail the proposed test.

Fix: Correct the expectation and retain independently calculated boundary cases.

S25 — minor — Targeted test commands inherit the whole-package 99% coverage gate.
Sections: Tasks 1–2 and subsequent targeted checks; pyproject.toml.

Problem/scenario: Commands such as uv run pytest tests/core/test_wire.py inherit coverage over all
src/simulatte with a 99% threshold. The feature tests can pass while the command necessarily fails
because unrelated modules were not exercised.

Fix: Disable aggregate coverage for targeted red/green checks, and enforce the unchanged 99% gate
on explicitly scheduled full-suite runs.

S26 — minor — Trace.verify() overpromises for KPI-only traces.
Sections: Spec §11.2; Task 10.

Problem/scenario: Verification promises to recompute the semantic digest, but KPI-only traces
intentionally omit the domain-event trajectory. Comparing the stored digest with itself would prove
nothing.

Fix: Define an explicit unsupported/not-verifiable outcome for that recording level, separate from
container-integrity validation. Also specify initial-state storage and cursor behavior for
activated traces with no domain events.

S27 — minor — Stamping can mutate an event that observers already retain.
Sections: Spec §6.1; Task 2.

Problem/scenario: env.emit stamps a frozen event using object.__setattr__, without a single-use
rule. Emitting the same instance twice changes the first retained reference’s sequence and ordinal.
Buffered records or history can then contain two references bearing the second emission’s identity.

Fix: Reject already-emitted instances or create a new stamped immutable record for each emission.
Test that previously delivered events remain unchanged.

Questions for Davide: None requiring a new product decision. D48–D53 can stand; these findings
concern contract completion, implementation boundaries and verification.
