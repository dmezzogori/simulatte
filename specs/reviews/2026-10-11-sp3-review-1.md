## Blocking findings

### R1 — P1: Observer events in existing chunks break released digest verification

**References:** spec §3 A2, lines 39–45; plan Tasks 0, 2 and 3; `src/simulatte/trace/reader.py:700`; `src/simulatte/events.py:337`; `src/simulatte/trace/writer.py:242`.

The compatibility statement only establishes that old readers accept null ordinals and empty deltas. The released Python `Trace.verify()` feeds **every** chunk event into `DigestAccumulator`, without skipping catalog entries whose category is `observer`. The live digest subscribes to domain events only. Adding observers to chunks therefore makes old readers report a digest mismatch on an otherwise valid file. New-reader changes alone cannot repair this forward-compatibility failure.

**Confirmed reproduction:** in a temporary directory, create a normal recorder, replace only its domain subscription with `"**"`, activate, emit a custom `ObserverEvent`, and close. The custom observer exposes an `ordinal` property returning `None` to get past the existing domain-only recorder assumption. The resulting trace yields `check(): pass`, `state_at(end): {}`, and `verify(): False`. No production source was changed. Separately, ordinary `ObserverEvent` has no `ordinal` attribute, so the proposed subscription swap also requires an explicit recorder encoding branch; it cannot reuse `_on_event` unchanged.

**Consequence:** users checking a valid 0.15 trace with the released reader receive an apparent reproducibility/integrity failure. This contradicts the optional-extension compatibility claim.

**Recommendation:** settle this in Task 0. Prefer an optional, separately framed observer record stream that old readers skip, preserving domain chunk and digest semantics. Both readers already skip unknown record types (`reader.py:341`, TS `trace.ts:386`). The new reader can merge observer records and authoritative KPI samples by `(t,seq)` for inspection/stepping. Define catalog publication, bounded record sizes, activation/prelude partition, truncation visibility, merged end bounds and KPI deduplication. An alternative is a required feature that makes older readers reject the file clearly, but that sacrifices the proposed forward compatibility and needs explicit approval. Add a released-reader verification test, not merely an old-reader decode test.

### R2 — P1: Recording all logs can recursively record the recorder's own size diagnostics

**References:** spec A2; plan Task 2.2/2.5; `src/simulatte/trace/writer.py:271`, `:370`; `src/simulatte/events.py:759`, `:778`.

`_on_event` invokes `_oversized` when a record exceeds `max_event_bytes`; `_oversized` emits `env.warning(...)`. A `"**"` subscription receives every log level. If that warning itself exceeds the configured threshold, recording it emits another warning. The bus queues reentrant emissions FIFO, so this becomes an unending diagnostic chain once observer encoding is corrected. Small positive thresholds are explicitly accepted by `ChunkLimits`; the issue does not require malformed input. Splitting observer records from domain chunks does not itself prevent this loop.

**Evidence status:** code-traced consequence of the proposed observer subscription, rather than a claim that the unmodified domain-only recorder currently loops.

**Recommendation:** explicitly exclude recorder-generated diagnostics from its own observation path, or report recorder failures/warnings through a separate non-recorded channel. Do not use the user-controlled `component` string as the sole exclusion mechanism. State the coverage exception in the feature contract. Test a threshold smaller than the warning itself, observer-heavy traffic, backpressure diagnostics, and multiple recorders. Include this policy in Task 2 before enabling observer coverage.

### R3 — P2: Linear KPI interpolation contradicts exact-cursor sample visibility

**References:** spec §8, lines 152–154; plan Tasks 3.2, 4.4 and 6.3.

The exact-event rule says samples with a greater `(t,seq)` are not visible, while the interpolation rule permits a value between adjacent samples surrounding the time. At a domain cursor at `t=5`, with samples `(0,1,0)` and `(10,20,10)`, linear interpolation produces 5 using an ineligible future sample. The documents do not choose whether this is allowed, suppressed, or replaced by a recorded value. Duplicate-time samples add another undefined case: a later-seq sample at the same time must not become the interpolation endpoint for an earlier exact cursor.

**Consequence:** implementations can produce different tiles for the same cursor while each follows part of the specification; the exact-state debugging promise and fixture oracle are underspecified.

**Recommendation:** distinguish exact-event and continuous-time tile rules explicitly. For exact-event mode, use only eligible recorded values (for example latest eligible sample for `linear`, labelled recorded rather than interpolated); never include a greater same-time seq. For continuous time, allow labelled interpolation between distinct-time brackets. At a sample time select the greatest eligible seq. Define `none` at a later event with the same timestamp and spell out the interaction with `gap`/`hold`. Add a small truth table covering before-first, between-samples, duplicates, non-finite gaps and after-last. Keep full-series chart drawing independent from the as-of tile.

### R4 — P2: Valid infinite event/footer times have no usable timeline contract

**References:** spec §§5–6 and §12.1–2; plan Tasks 3.2 and 4; `src/simulatte/_wire.py:212`; TS `trace.ts:576`; `src/simulatte/trace/writer.py:530`.

The existing wire contract allows infinite simulation times; the readers reject NaN times but accept infinities. The draft covers infinite **motion end** times, not infinite recorded event or footer times. A seek bar normalized over an infinite range, fit-to-range charts, or playback toward an infinite end cannot follow ordinary finite-time behavior.

**Confirmed reproduction:** run a process that yields `env.timeout(float('inf'))`, then emits one domain event, and let the environment exhaust. The shipped writer and reader produce `cursor_range == ((0.0, -1), (inf, 0))`; `check()` passes and `verify()` returns `True`.

**Recommendation:** specify a finite playable interval derived from finite recorded times or an explicit finite user window, with a visible unbounded/non-finite-time diagnostic. Preserve non-finite-time events as inspectable records and define whether exact stepping to them produces an inspection-only position or is disabled. Do not silently classify this valid wire input as corruption or silently coerce its time. Add fixtures for infinite footer/event time, no finite event after activation, and finite-prefix-plus-infinite-tail traces. Export should retain its existing finite-window requirement.

## Nonblocking suggestions and clarifications

### S1 — Job transfer rendering needs the shipped location vocabulary

**References:** spec §7 adapter table and Decorative transfers; plan Task 5; `src/simulatte/server.py:342`; `src/simulatte/psp.py:173`; `src/simulatte/job.py:442`.

There is no single recorded `job.transferred` event. The shipped sequence includes `job.released`/`psp.exited` setting `location="transit"`, followed by a queue/grant event setting the destination. Jobs also use null and `"done"`, and server/pool locations are prefixed strings. At an exact release cursor the state is transit, not already at the next server. The spec's general unplaced tray can represent this honestly, but the built-in adapter and trail contract should explicitly say so and identify the destination event that triggers decoration. Preserve the intervening exact cursor; do not infer destination from a later event or conflate queue arrival with operation start. Test release → transit → queue → grant at the same time and across chunk boundaries.

### S2 — Catalog reference-based filtering currently has no declared reference fields

**References:** spec §8 line 150; plan Tasks 3 and 6; `src/simulatte/events.py:357`.

`FieldInfo` records name, wire type, nullability and presentation status, with no entity-reference metadata. Delta-target filtering works, and the spec already offers text search when metadata is missing, so this is not a blocker if that is the intended initial capability. State that limitation explicitly for existing/custom empty-delta events. If richer reference filters are required in SP3, add a reviewed metadata extension or a trusted versioned built-in reference registry with ownership and tests; do not infer references from arbitrary string payloads.

### S3 — Make the browser performance gate cover main-thread stalls, not only frame averages

**References:** spec §5 and §12.6; plan Tasks 1, 3, 5 and 10; TS `container.ts:58`, `trace.ts:451`, `deltas.ts:36`.

The existing reader can synchronously decode a chunk up to 256 MiB and replay collection operations that copy arrays. The proposed cache budget bounds retained working sets, not a single decode/replay stall; cancelling fetches also does not interrupt synchronous decoding. The draft correctly calls for congested workloads and provisional measured limits. Include maximum/long-task duration and cancellation responsiveness during cold seek/indexing in that evidence. Choose a worker or a bounded/cooperative strategy if needed; do not infer responsiveness from bounded cache bytes or the absence of React commits. This is a feasibility measurement, not evidence that the proposed architecture necessarily fails.

## Overall assessment

The draft has strong explicit boundaries for stale async work, exact versus continuous positions, generic delta replay, retirement, bounded exports, Safari evidence and offline packaging. A1's separate optional display record is a sound compatibility direction; current readers ignore additional KPI record members while validating declarations strictly. A3 is consistent with the existing portable motion map and requires no simulation execution in the viewer. These positives do not resolve R1–R4. Correct the contracts and dependent plan tasks before seeking implementation approval; no implementation was reviewed or executed.
