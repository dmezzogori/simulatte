## 1. Outcome and boundaries

`simulatte studio plant.py:build` opens a local workspace with parameter forms, layout editing, run/cancel controls and live recorded progress. Every run uses immutable source and input bytes in a fresh execution process. Source, parameter, seed, stopping-policy and physical layout changes produce a new execution request; presentation edits reuse the trajectory when the stored physical dependency closure proves that safe. `simulatte run` uses the same coordinator without a browser or web dependencies.

Plain Python scripts, `Runner`, undecorated builders, `simulatte view`, offline HTML and media export remain supported. Playback pause/seek controls the recorded view, never the running simulation. Experiments, replications, statistical comparisons, SSH transport, uv provisioning and automatic retention remain SP5. SP4 has one local execution slot per coordinator, one active Studio revision, and a minimal history of single runs. There is no experiment scheduler hidden behind the UI.

## 3. Choices and contract gaps

Chosen approach: a transport-independent execution package, one trusted supervisor, one-use execution children, durable segment transfer, and the existing viewer extended to consume committed prefixes. Rejected: running Python inside the ASGI process (blocks cancellation and leaks imports); reusing model interpreters (violates D29); restarting the entire web server on file changes (loses sessions and revision ownership).

| Deferred choice | SP4 decision |
| --- | --- |
| Frame encoding | Worker protocol 1.0: fixed magic, u32 big-endian length, MessagePack control envelope plus bounded raw binary payload; existing pure-Python-capable `msgpack`. No pickle. |
| Module boundaries | Public metadata in `model.py` and stopping primitives in `stopping.py`; internal `execution/`; shared server security plus `studio/app.py`, `watcher.py`, `websocket.py`. |
| Watcher | `watchfiles` only in `[studio]`, custom manifest-aware filtering, polling fallback and periodic reconciliation. Never Uvicorn reload. |
| Import tracking | Manifest determines what is watched; guarded import resolution and module-origin inventories validate snapshot loading throughout execution. Imports never shrink the watch set. |
| Spool | 256 MiB/1,024 files per attempt, 16 MiB transfer windows, explicit durable ACK, cancel-aware blocking, 60 s no-ACK failure deadline while full. |
| Warm spare | Zero by default and no warm-spare implementation in SP4. Measure cold process costs. D45/C4 permits spares; it does not require a pool. |
| Source capture | Copy working-tree bytes from an explicit manifest into content-addressed storage; normalized uncompressed PAX tar artifacts, detached read-only per-attempt materializations. No hardlinks to editable files and no `git archive HEAD`. |

The following **clarifications/amendments were approved on 2026-10-11**:

1. **A1 — publication, C5.1:** a filesystem rename and a SQLite commit cannot literally be one cross-resource transaction. Define atomic *visibility*: durable immutable artifact directory first, fenced SQLite commit second, recovery of unindexed directories on restart. Readers see only indexed committed results. Amend the master wording on approval.
2. **A2 — finite population, C3/C5.5:** the master specifies cutoff/drain semantics but no way for generic Python models to identify arrivals, pending arrivals or completion. Add the explicit `Population` contract in §5. Never infer drained state from all registered entities or SimPy's queue, which may contain perpetual observers/charging processes.
3. **A3 — snapshot discovery, C3/C5.2:** decorator metadata, including `inputs`, requires importing code before inputs are known. Add a disposable metadata inspection phase from a source-only snapshot; importing a model must not read declared data or run simulations. Reads belong in `build`/stages/processes. No coordinator/supervisor imports user modules. This restriction and the non-Git include requirement must be visible in docs.
4. **A4 — readiness, C1.10:** current projection callbacks run before `_activated` is set; `activate()` then immediately drains queued commands. Add an internal readiness barrier after projection capture/activation bookkeeping and before draining that queue. Acknowledging `ready` outside `activate()` after it returns is too late.
5. **A5 — immutable inputs and cleanup limits:** immutable snapshots isolate supported model reads from editor changes; they are not a hostile-code sandbox. POSIX process groups cannot contain deliberately detached `setsid` descendants. Document this limitation as C4 allows, reject unsupported editable import mechanisms, and test ordinary descendants plus parent death. Do not claim universal OS containment.
6. **A6 — source membership:** C5.2 leaves explicit listing of untracked source ambiguous in Git projects. Use `bundle.include` as additive explicit membership in Git projects and mandatory source membership outside Git. Excludes cannot remove the selected model or declared inputs. The configured layout path is always separate, even if tracked or declared as an input (reject that conflicting declaration).
7. **A7 — schemas:** introduce execution protocol/store/request schema 1; preserve trace 1.2 and layout 1.0. Execution metadata is an optional trace feature `execution-v1` under container 1.3, retaining old-reader check/verify behavior. It carries normalized request/stopping and execution provenance; it changes no event or KPI arithmetic. Amend C1.7 and the trace spec before implementing this extension.

## 4. Python entrypoint and parameter contract

`@simulatte.model(params=Params, horizon=..., warmup=0, time_unit=None, inputs=(), stop=None)` attaches frozen `ModelSpec` metadata as `__simulatte_model__` and returns the same callable. `get_model_spec(build)` is the supported accessor. Exactly one of `horizon` and `stop` is required. `build(env, layout, params) -> None` is synchronous and must not activate, step or run the environment; execution guards reject those operations during build. It may schedule processes, attach collectors and register layout stages.

`Params` is a frozen dataclass. Fields support exact `bool`, safe `int` (±(2**53−1)), finite `float`, `str`, scalar `Literal` and `Enum`, optionally wrapped in `Annotated`. `Range(min=None,max=None)` is inclusive numeric validation; `Description(text)` supplies help; `Length(min=0,max=...)` applies to strings. Reject unknown metadata, mixed/duplicate Literal values after wire normalization, nested containers, unions, `Any`, non-finite defaults and ambiguous Enum values. Enum transport uses the member name, with labels from that name; values may be scalar but do not identify the member. No arbitrary validator functions or default factories: schema discovery must not evaluate a second source of dynamic defaults. Dataclass `__post_init__` may enforce cross-field validation in the execution child; failures are field-independent validation diagnostics before `ready`. Required fields have no default and must be supplied.

The schema contains version, model name/docstring, ordered fields, exact type, choices, constraints, descriptions and defaults. Validation occurs both at request creation against the data schema and in execution when constructing `Params`. Browser validation is advisory. CLI booleans are `true`/`false`, integers decimal, floats finite decimal/exponent, strings literal text, Literal values parsed by their declared type, Enums by member name. Unknown/duplicate `--param` keys fail; never `eval`. Float-typed inputs normalize `1` to `1.0`; bool never passes int validation; signed zero normalizes to +0 for request parameters. Large seeds travel as decimal strings, separately from safe-integer parameters.

Several models in one file require `:name`; a sole decorated model is selected automatically. `--model-list` is not needed: ambiguous selection returns the available names. Import exceptions and syntax errors carry project-relative filenames, bounded traceback and phase `inspect`/`prepare`/`run`.

## 5. Stopping, artifacts and preparation

Public `Horizon(until, warmup=0)` normalizes decorator `horizon`/`warmup`; require finite `until > 0` and `0 <= warmup < until`. Preserve the existing half-open horizon window `[warmup,until)` and SimPy boundary behavior.

Public `FinitePopulation(arrivals=N | cutoff=T, safety_limit=S)` requires exactly one cutoff, nonnegative safe N or finite T, finite S>0 (S>T for time cutoff), and warmup=0. The stopping policy is data and part of request identity. A finite model binds one `Population(env, policy=None)` during build (the execution driver supplies the normalized policy through the environment; plain scripts pass it explicitly) and calls:

- `admit(key: str) -> bool`: register one unique active population unit if arrivals remain open; return false once closed. Count cutoff closes on the Nth admission, including N=0 at time zero.
- `complete(key: str) -> None`: discharge exactly one admitted unit after its final domain transition. Unknown/duplicate completion fails.
- `pending(key: str)` / `unpending(key: str)`: bracket scheduled arrival work that has not yet been admitted or abandoned. Keys are unique; on closure generators must abandon pending work. Completion requires zero active and zero pending units.

The runtime exposes `population.open` and a closure event for arrival generators, closing time-based admission at T (admissions at T are refused). This is behavioral model control, not a collector. Existing core components do not automatically claim to be the population; an example shows job submission/completion integration, another covers fleet orders. Default production metrics remain attached as today.

Drain is evaluated after a completed simulation step/queued-command batch, at the first point at or after cutoff with zero active/pending. T_end is that cutoff/draining transition time, not the time of a later housekeeping timer. Count N never reached, unresolved pending arrival, stalled capacity or infinite same-time work cannot be called successful: exhaustion before cutoff/drain fails `population_incomplete`; reaching S without drain fails `safety_limit`; optional wall timeout covers nonadvancing time/CPU loops. At S, process ordinary same-time work before the final safety decision so a completion exactly at S succeeds; cap is enforced without requiring the ordinary queue to empty. Finite successful windows are `[0,T_end]`, consistent with existing terminating collectors; zero-duration denominators retain each collector's defined empty result.

The internal execution driver records the normalized policy and completion reason without `env.run(until=event)` overwriting it with an opaque event policy. Plain-script run semantics stay unchanged. Fingerprints remain domain digest plus common KPI scalars; recording level and wall-time diagnostics cannot alter them.

Execution order: verify snapshot/runtime → load selected metadata → validate params → create `Environment(seed,time_unit,provenance,artifacts_dir)` → configure warmup/KPI selection → attach recorder → create/load Layout → guarded build → layout stages/validate/bind/finalize → initializers/capture → durable INITIAL plus `ready` → coordinator acknowledgement → queued commands → stepping driver → final scalars, trace close, artifact enumeration → result proposal. Cancellation before `ready_ack` releases the barrier without simulation. Preparation failures never report running.

`env.artifacts_dir` is a writable per-attempt directory outside the read-only snapshot; optional in plain scripts. Model outputs are regular files beneath it; reject escaping symlinks, special files and paths. No external side effects are rolled back. The model remains retry-safe by contract. The final scan hashes artifacts; files must stop changing before publication.

## 6. Snapshot and identity

Project root: explicit `--project`, otherwise nearest parent `pyproject.toml`, otherwise Git top-level, otherwise the model's parent. Model/layout/input paths must remain inside it. Read `[tool.simulatte.bundle] include`, `exclude` and optional `python-path` (relative import roots, default project root and existing `src`). Discover local workspace/path packages from project metadata and installed distribution `direct_url.json`; reject external local packages or ambiguous import roots rather than silently use editable code. No uv project is required locally.

Git membership uses `git ls-files -z --cached` but reads current disk bytes, including unstaged edits. Missing tracked files are recorded as absent, not read from HEAD. Reject unresolved merge entries and submodule gitlinks with instructions to list supported in-root source explicitly. Add explicit include files/globs and declared inputs, remove configured excludes and reserved runtime directories (`.git`, `.simulatte`, virtual environments, caches). Untracked/ignored files are never added just because they exist. A selected model absent from membership is an actionable preflight failure. No implicit secret-file glob.

Capture regular bytes with no-follow opens and identity checks, canonical project-relative POSIX paths, sorted UTF-8 ordering, byte lengths, SHA-256 and executable bit. Reject traversal, case-fold/path-normalization collisions, nonportable names, special files and escaping symlinks. Internal symlinks are materialized as regular content after target validation; record their target relation and capture the target once consistently. Cap default capture at 1 GiB and 100,000 files; configurable in project bundle settings. These are product limits, not memory allocations.

Copy into a private staging tree; re-enumerate membership and compare per-file identity/digests after copying. Retry the whole capture at most three times on change, then report `snapshot_changed` and wait for stable edits. There is no portable atomic multi-file filesystem snapshot; the guarantee is the exact captured manifest/bytes, with observed races rejected, not a transaction spanning arbitrary concurrent editor saves. Studio waits 250 ms quiet before capture. Each run uses that materialized snapshot only; subsequent edits cannot affect it.

Metadata inspection first uses the source snapshot in its own disposable execution child (same containment and diagnostics). It returns only serialized specs. Capture declared data inputs after inspection, combine with the unchanged source, and import/validate metadata again in the actual run; mismatched metadata fails. Cache inspection by preliminary source hash and runtime identity, never by mtime; the final source hash is recomputed after separating declared inputs. Record project file opens during inspection and reject any that turn out to be declared data inputs; this supports the import-time discipline, not hostile-code sandboxing. Input-dependent module imports must be moved into build. Inspect and run never share an interpreter.

Use domain-separated SHA-256 over `_wire.canonical_pack` for typed manifests and requests, with explicit schema versions. Source hash excludes configured layout and declared input bytes; input hash is a separate sorted path/content manifest. A file cannot simultaneously be source and declared data input: remove declared inputs from source membership after discovery. Preserve dirty working-tree bytes, not Git commit identity. Package metadata/config belongs to source unless explicitly excluded. Layout hash uses SP2 normalization, separately from the monotonic revision token used for concurrency.

Store normalized uncompressed PAX archives in `snapshots/<hash>/`: sorted regular-file entries, uid/gid=0, empty owner names, mtime=0, modes 0644/0755, deterministic PAX headers. Store both canonical manifest hash and archive SHA-256; never identify semantic content solely by timestamps or archive implementation details. Materialize manually from validated entries (not unrestricted extractall); verify before use. Attempts get independent read-only copies/reflinks, never shared writable hardlinks. Disable bytecode writes. Recheck input/source hashes at completion; detected mutation fails provenance. Read-only permissions are accidental-write protection, not an OS sandbox.

Launch inspection/execution with `-I -S` and a small trusted bootstrap. Supply stdlib, the trusted Simulatte runtime and allowlisted external site-package directories explicitly; map all local packages to snapshot import roots before user import. Do not execute `.pth`, `.start`, `sitecustomize` or `usercustomize`; safe non-executable external path entries may be resolved explicitly. Check venv paths across Python 3.11–3.15, since `-S` prefix behavior differs. Unsupported dependencies requiring startup hooks fail with a concrete diagnostic. Bootstrap does not import model code to discover roots. Trusted runtime identity includes Simulatte version and package-content digest, so a development installation is not treated as an immutable version string. Freeze an editable trusted runtime into a separate content-addressed tool copy before starting the supervisor; it must not later import coordinator-working-tree bytes. If Simulatte itself is a local package of the model project, the execution child loads that package from the attempt snapshot and verifies protocol compatibility; the trusted supervisor keeps its own frozen runtime. Never preload the editable package into the child and then try to fix its origin by changing sys.path.

Guarded finders/loaders validate module origins, namespace package locations and lazy imports before executing local code. Record `sys.modules` origins at ready and finish, plus newly resolved origins during execution. Local modules from the editable tree or unbundled local paths fail; external packages stay in the user's environment and their versions/origins are recorded. Custom import loaders/dynamic absolute-path file reads cannot be comprehensively sandboxed: detect supported origin violations and mark unknown provenance incomplete, never claim that an audit hook proves isolation. Import tracking is diagnostic/validation; watcher membership remains the full manifest.

## 7. Execution modules and worker protocol

| Module | Responsibility |
| --- | --- |
| `model.py`, `stopping.py` | Optional public metadata, constraints and population API; no web dependencies |
| `execution/schema.py`, `hashing.py` | Typed versioned messages, request normalization and identity |
| `execution/snapshot.py`, `imports.py` | Manifest/capture/materialization and isolated import validation |
| `execution/protocol.py`, `transport.py` | Bounded codec and local stdio transport; future SSH implements same interface |
| `execution/supervisor.py`, `process.py` | Trusted worker lifecycle, control loop, platform cleanup and stdout/stderr drains |
| `execution/bootstrap.py`, `child.py` | One-use inspect/run process; all user imports and model execution |
| `execution/spool.py`, `trace/sink.py` | File/segment recorder sinks, quota, segment commit and ACK reclamation |
| `execution/store.py`, `coordinator.py` | SQLite ownership, request/attempt state, publication, revision scheduling |
| `studio/auth.py`, `app.py`, `websocket.py`, `watcher.py` | Shared auth, Studio routes, UI protocol and file invalidation |

Supervisor starts through `simulatte worker --stdio` (internal CLI, core install). It accepts one inspect/run at a time. It never imports a model, evaluates annotations or validates user callbacks. It may remain alive across requests, but every child runs once and exits. Use independent I/O/control threads or tasks so slow diagnostics/trace transfer cannot stop cancellation or heartbeat generation.

Protocol preamble is `b"SIMWORK\x00"` once, followed by frames. Frame = u32 BE payload length + payload. Payload = u32 BE envelope length + canonical MessagePack map + optional raw bytes. Map fields: `v:[1,0]`, `type`, monotonic per-direction `seq`, nullable `request_id`, `attempt_id`, `generation`, and typed `body`. Raw bytes are allowed only for artifact/trace fragment messages; never interpreted as Python objects. Max frame 2 MiB, max envelope 256 KiB, max fragment 1 MiB, nesting 64; zero/oversized/truncated frames, duplicate map keys, unknown mandatory message types and invalid ids are fatal protocol errors. Large manifests/layout metadata use verified artifact references, not oversized control frames. Before hello allow at most 64 KiB bootstrap noise for 10 s; after magic never scan forward to resynchronize corruption. Envelope values reuse the wire subset, with fixed limits validated before allocation.

Messages: `hello`, `inspect`, `model_info`, `run`, `ready`, `ready_ack`, `cancel`, `cancelled`, `heartbeat`, `progress`, `trace_chunk`, `artifact_fragment`, `ack`, `kpi`, `diagnostics`, `result`, `error`, `shutdown`, `bye`. `hello` advertises protocol/Simulatte/runtime/platform, framing limits and cleanup capabilities. Reject incompatible major or unsupported required capabilities before scheduling; minor fields are ignorable only where schema says optional. `run` contains the immutable request and snapshot references; `ready` references the actual resolved manifest. Every attempt message is fenced, including progress and ACKs. Duplicate artifact fragments/ACKs are idempotent only with identical hash, offset and length.

Supervisor heartbeat every 1 s; coordinator loses worker after 5 s without a received heartbeat (monotonic clock). Report elapsed wall time, child phase, last known simulation time/event count, spool occupancy and backpressure. Progress at most 5 Hz; no progress for 10 s is `stalled`, not worker loss or automatic failure. `--timeout` optionally bounds the entire attempt including preparation. Transport loss is separate from simulation stall. A fully blocked stdio stream may prevent heartbeat delivery; the coordinator then loses that transport even if the supervisor is alive.

Capture OS stdout/stderr descriptors, not just Python `sys.stdout`, from child startup onward. Drain each independently in bounded pieces; retain 1 MiB tail per stream, emit at most 64 KiB/s per attempt, count dropped bytes and report truncation. Model text cannot inject protocol frames. Structured error contains phase/code, bounded message and up to 64 KiB traceback. Diagnostics are not semantic events; recording them must not recurse through the event bus.

Cancellation sets a control event checked between steps and while waiting for spool credit/readiness. Allow 2 s for normal trace close; then POSIX SIGTERM to the process group, 1 s later SIGKILL; wait/reap. On Windows request cooperative stop then terminate the Job Object. Cleanup also runs after success/error so model-started background children do not survive. Supervisor stdin EOF ends children and exits. Linux/macOS use a separate trusted guardian process watching an exclusive supervisor-lifetime pipe and killing the execution group on EOF; guardian is outside that group, and user descendants never inherit the pipe's write end. This avoids relying on a Python watcher thread while user code holds the GIL. Windows creates the child suspended, assigns a kill-on-close Job Object before resuming, and disables breakaway. Fail preparation if Job assignment is unavailable; do not silently run without containment. POSIX deliberate detachment is the documented limitation in A5.

## 8. Trace spooling, flow control and live reads

Refactor the writer's output into a sink with `write`, logical `tell`, `flush/commit` and `close`; default file sink retains exact released bytes. The segment sink commits a file only at a valid logical boundary: preamble+HEADER; each standalone record; CHUNK+matching INDEX together; FOOTER+trailer together. Offsets remain cumulative, so concatenation yields a normal 1.x trace. Write temp, flush/fsync, atomic rename, then notify supervisor. HEADER/INITIAL/catalog/KPI/OBSERVERS must be transferred too; shipping only domain chunks loses live preparation and metadata. No wire-format replacement is needed for this transport.

Default attempt spool quota 256 MiB and 1,024 committed/pending files includes reservations for the active temporary segment. Maximum single committed segment 128 MiB; reject a segment that cannot fit rather than wait forever. Retain the current 64 MiB writer pending-byte budget and INITIAL limit; account separately for serialization working memory. Segments travel in ≤1 MiB fragments under a 16 MiB in-flight window. Scheduling control frames between fragments bounds heartbeat/cancel latency. Only fsynced coordinator staging plus a durable segment-receipt record earns an ACK; browser receipt is irrelevant. ACK deletes the supervisor's spool file and releases quota. Duplicates compare identity/hash, gaps stay unpublished, and wrong hashes fail the attempt.

When no credit remains, block the recorder writer and then its bounded producer queue; do not drop domain/KPI data. Supervisor reports `backpressure` while the simulation is blocked, suppressing the misleading `stalled` label. Resume when an ACK releases space. ENOSPC/EDQUOT is `disk_full`. Full spool with no durable ACK for 60 s terminates `disk_full` with reason `spool_unreclaimable`; slow consumers that keep acknowledging can remain blocked without a wall deadline unless `--timeout` is set. Coordinator loss triggers immediate cleanup; if already full/unreclaimable preserve that reason in local diagnostics. Cancellation never waits for a new credit or data ACK.

Coordinator keeps a durable contiguous trace prefix and a segment index. Partial fragments are never visible. HTTP exposes immutable prefix generations identified by `(attempt,generation,length,digest)`; ranges cannot pass that prefix length, even as a later prefix grows. It also serves immutable segment bytes by opaque id. Authenticated websocket `trace_available` carries generation/byte count/last cursor, not the trace bytes. Browser lag does not backpressure the worker because the coordinator receives independently.

Add `LiveRecording` to the TS reader: retain existing decoded-cache limits, extend the metadata index only from the last committed offset, validate new catalog/KPI/INDEX records, and reject a non-prefix extension or attempt switch. Reuse parsing/replay helpers with static `Recording`; no full rescan per update. A new reader generation atomically publishes history bounds after validation. Playback follows latest available data only in explicit Follow mode; manual seek/step disables following. At the live edge show buffering until a new committed cursor exists. KPI tiles obey existing exact/continuous cursor rules and cannot show uncommitted samples. Live status comes from coordinator state, not absence of FOOTER.

At most two reads and four decoded chunks/128 MiB estimated cache remain; pending updates coalesce to the newest prefix. Old fetch completions cannot overwrite the current attempt/revision. Failed/cancelled provisional streams become visibly invalid and return to the last good committed run. Exports in Studio use a pinned committed result and a pinned presentation overlay; live exports are disabled until completion. Static view/player exports retain their existing behavior and caps. Offline HTML with a presentation overlay contains the original trace plus an explicitly labelled, validated presentation-only overlay, never rewritten simulation history; the player uses the same overlay resolver result as Studio.

## 9. Coordinator and minimal run store

ExecutionRequest schema 1 contains model path/name, source/input manifest hashes, normalized layout content hash and captured layout revision, typed params, decimal seed, normalized stopping policy, recording level, KPI selection, requested runtime/provisioning identity and schema versions. All are known before scheduling. Request id is its canonical hash. Wall timestamps, attempt ids, machine names and browser state are excluded. ResolvedManifest adds actual runtime/platform, distribution set and import evidence, physical/full/layers hashes, physical dependency closure, capabilities and completeness warnings. Store both; do not overwrite the requested identity with discovered facts.

A revision is a persisted monotonic number plus input-set digest: source, inputs, model schema, layout content, params, seed, stop, recording/KPIs/runtime. Even editing back to identical bytes yields a new concurrency token, preventing ABA writes; identical requests can still reuse content. User edits and watcher changes serialize through one coordinator command queue. One active attempt is identified by `(request_id,attempt_id,generation)`; fencing changes in the same SQLite transaction that assigns/revokes it.

State path: queued → preparing → ready → running → finalizing → succeeded; terminal alternatives validation_failed, failed, cancelled, lost, superseded, disk_full. Stalled/backpressure are nonterminal flags. Automatic retries are zero in SP4; explicit rerun creates a new attempt, preserving at-least-once-safe semantics without hiding duplicate side effects. Late messages cannot mutate a terminal/current replacement attempt. Cancelling invalidates provisional visibility immediately, then waits for cleanup. A failure to clean up prevents reuse of that worker slot and is reported.

Store layout:

```
.simulatte/
  index.sqlite
  coordinator.lock
  snapshots/<content-id>/{manifest.msgpack,source.tar,inputs.tar}
  staging/<attempt-id>/{trace-prefix,segments/,artifacts/,receipt-log}
  results/<attempt-id>/{run.simtrace,manifest.msgpack,artifacts/}
```

SQLite schema 1: metadata/schema version; snapshots; revisions; requests; attempts with assignment generation/runtime/status/timings; segment receipts; results; KPI scalars; artifacts (relative path/size/hash); presentation views linking a result and re-resolved layout bundle. No experiments tables yet. Use stdlib sqlite3, foreign keys, explicit transactions compatible with Python 3.11, WAL and synchronous FULL. One OS lock holder owns coordinator writes per project; a second CLI/Studio invocation fails with a clear busy message, never steals a live lock. Read-only result access may coexist. Use a local filesystem; network filesystems are unsupported for the index/lock.

Publication A1: close trace and outputs → verify contiguous bytes/checksums, Trace.check/verify, outcome and manifest/fingerprint equality → fsync staging → rename to immutable result directory on the same filesystem → fsync directory where supported → transactionally compare the active assignment generation, insert result/KPIs/artifacts and mark succeeded. A failed fence leaves an unindexed directory for recovery, never a visible result. Publication also waits for execution exit and descendant cleanup, so a remaining writer cannot mutate final artifacts. Only indexed committed results participate in reuse/reproduction. Crash injection at each boundary must demonstrate either one valid result or no published result. On startup mark orphaned active attempts lost; remove/quarantine partial staging and unindexed result directories after checking no active owner. Do not adopt an unindexed result automatically. Forward migrations are transactional; unknown newer schema refuses access. Store deletion is safe only after stopping its owning processes.

Presentation-only edits create a new view/revision linking the original committed result plus a new LayoutBundle. They never mutate the trace or original resolved manifest. Reuse requires all non-layout request inputs equal and `reresolve_presentation` returning a reusable bundle with unchanged physical hash. During a running attempt, use its ready bundle to classify edits: a presentation revision can follow that same attempt through an explicit view association; simulation result retains its original request. Physical/unknown changes fence it and rerun. Without a valid ready bundle, treat edits conservatively as requiring preparation. Last good view remains labelled with its old revision while a new one prepares or fails.

Reproduction: `run --reproduce REQUEST_ID` loads stored snapshots and normalized inputs, makes a fresh attempt and compares runtime/manifests/fingerprint; no automatic installation or changed-runtime equivalence. Report missing snapshot, unavailable runtime, incomplete provenance or fingerprint mismatch explicitly. This is a single-run reproducibility path, not SP5 experiment replay scheduling.

### Trace provenance extension (A7)

Keep execution identity out of event payloads. Under optional `execution-v1`, `HEADER.execution` is `{schema:1, request_id, request}`; `INITIAL.execution` is `{schema:1, resolved}`; `FOOTER.execution` is `{schema:1, termination, actual_end}`. Request/resolved values are the schema-1 wire maps in §9; paths inside them are project-relative and source/input file listings live in referenced stored manifests rather than duplicating archive contents. The resolved object includes enough runtime/dependency/hash/completeness data for offline inspection; the layout bundle already carries the closure. Unknown optional metadata remains ignorable. Readiness has the same resolved mapping as INITIAL, and the final result must match it. Enforce the existing record/INITIAL limits and the 128 MiB segment cap; fail preparation on excessive metadata instead of emitting an unreadable trace. No optional field may become necessary to verify the original domain digest.

Populate the existing `RunManifest.requested.parameters` from the validated parameter values before recorder creation (currently Environment leaves them empty), preserve provenance hashes, and record normalized final stopping policy in the existing final manifest. Add only optional constructor/internal context fields; ordinary script defaults remain empty parameters/unavailable caller provenance. The execution driver must finalize timing/failure/policy bookkeeping even when it advances with `step()` rather than `run()`. Test complete manifests and common KPI/fingerprint equality across both drivers, not just the optional extension's presence.

## 10. Server and websocket contract

Keep Starlette/Uvicorn, single ASGI process and no reload. Add `watchfiles` and an explicit `websockets` dependency to `[studio]`; bare Uvicorn does not guarantee a websocket backend. Configure asyncio, websockets backend, bounded queue, disabled per-message compression, disabled proxy headers/access logs. Pin compatible versions in `uv.lock` during implementation; no need to upgrade unrelated frontend packages.

Bind only `127.0.0.1`, port 0 by default; preserve optional local `--port`. Reuse SP3 bootstrap, random instance cookie and sessionStorage secret, no-referrer/no-store, nonce CSP and `location.replace`. Reload retains credentials; new tabs recover using terminal `link` (new unused token invalidates the previous unused token). Cookie alone cannot fetch/regenerate the secret. Assets contain no project data. Never log credentials; terminal handoff is deliberate, as in SP3.

Require exact canonical Host+port. Mutating HTTP requests and websocket upgrade require exact Origin; do not trust forwarded headers. All project/trace reads require cookie+secret, even if nonmutating. A websocket has cookie/Host/Origin checked before accept, then must send `{v:1,type:"auth",secret}` within 5 s before any data or command; no secret in URL/subprotocol/log. Invalid auth closes 1008, wrong protocol 1002, oversize 1009. No CORS and no arbitrary filesystem routes. Limit to 16 authenticated tabs and 4 unauthenticated pending sockets.

After auth, JSON envelope `{v:1,type,id,revision,attempt_id?,generation?,body}`; response echoes id, notifications add monotonic `event_seq`. Commands: `state.get`, `params.set`, `run.start`, `run.cancel`, `layout.get`, `layout.validate`, `layout.write`, `view.select`. Notifications: `state`, `model_info`, `revision_changed`, `run_state`, `progress`, `trace_available`, `kpi`, `layout_resolved`, `validation`, `inputs_changed`, `invalidated`, `error`. No experiment messages accepted in v1. Float specials in KPI/diagnostics use an explicit tagged JSON value, not invalid JSON NaN; user maps cannot be mistaken for tags because the field schema fixes their position.

Every mutating command carries the base revision and an idempotency id. A stale command returns `revision_conflict` plus current revision, never writes/runs. `run.cancel` additionally identifies the exact attempt; it cannot cancel a newer attempt on retry. Cache 256 command outcomes per connection session; after reconnect non-idempotent retries reconcile state before resending. Server send queue ≤256 messages/4 MiB; progress/KPI/availability coalesce by attempt/key. Terminal/revision messages are never silently dropped: disconnect a slow tab with 1013 and require state resync. Reconnect gets a complete authoritative state snapshot and immutable artifact descriptors, not an unbounded event replay.

JSON control frames ≤256 KiB, depth 64; layouts/bundles larger than control limits use authenticated HTTP references. Layout HTTP PUT supports the existing 16 MiB layout cap and base revision header, validates streaming body size before parsing, and shares coordinator serialization with websocket writes. No general uploads. Trace range endpoints use opaque store ids and immutable generation ETags, never path parameters from the user. Layout writes target only the configured in-root regular-file path, with symlink-safe parent checks, validation and atomic replacement; re-read disk identity immediately before replace. All model/trace/layout text remains escaped text.

## 11. Forms, layout editor, revisions and watching

Add Parameters and Layout panels to the existing shell. Parameters show type, default, range/choices and description; required/invalid values block Apply. Apply is one revision change; typing does not rerun. Include seed, stopping policy, recording level and KPI selection. Preserve drafts on server validation errors; source-schema changes retain only still-valid matching fields, visibly flag incompatible fields, and do not coerce silently.

Layout supports selection/multiselect, drag, rotation, numeric position/footprint/port editing, snap toggle, exact coordinates and grid settings; visual color/label/icon; obstacle flags and blocked areas; lattice bounds/connectivity/clearance; lane creation, stable vertex ids, move/insert/delete; explicit node/arc editing; connector properties; enabled/direction/speed/node-capacity overrides and selectors. Use schema-validated forms plus canvas handles, not a raw JSON box as the sole editor. No model logic creation. Network previews use Python validation/resolution in a disposable preparation child where physical regeneration is needed; a ghost drag alone never claims a valid physical graph.

Gesture edits stay local until pointer-up/Apply; one action produces one patch/history entry. Undo/redo commits inverse/new patches against the latest revision, not old whole-file snapshots. A conflict preserves the draft and offers reload/reapply after review; never last-writer-wins. Show inherited auto/code/file provenance, Reset (remove override), and Remove optional value (`$unset`). Lists replace wholly per SP2. Physical writes to generated ids fail, presentation overrides warn. Orphans, kind mismatches, stale lane segment overrides and connector failures are listed with explicit reassignment/delete actions; never auto-transfer overrides to new vertices. Use z=0 and existing y-up transform/snapping rules.

Watch root recursively with `watchfiles.awatch`, custom reserved-directory filter rather than its Python-only/default exclusions; quiet debounce 250 ms, maximum batch age 1 s. Watch Git index/HEAD metadata separately so staging new files or branch changes updates membership; recompute explicit include/glob membership after directory events. Added untracked files outside explicit membership do not rerun; show missing bundled imports as actionable errors. Declared data input changes, including non-Python extensions, always count. Record newly declared inputs after metadata changes. Polling fallback is supported; rescan manifests every 5 s and on focus/manual refresh to recover missed notifications. Check content hashes, not mtimes alone; permission errors visibly suspend auto-run.

Ignore owned `.simulatte` writes and match an editor's own saved content hash to avoid duplicate reruns. A source/input change invalidates current provisional data immediately, debounces snapshot creation and starts exactly one latest request. Physical layout/parameter changes do the same. Presentation-only changes use pure-data re-resolution and notify the scene without a child spawn; a field normally visual becomes physical if the closure says so. Invalid external JSON/source leaves the last good committed run on screen with diagnostics and auto-run paused for that invalid revision. Revisions advance on external changes too; compare current disk hash before every editor save to catch changes not yet delivered by the watcher. Commands and async validation results are revision-fenced. Atomic compare-and-replace against an uncooperative external editor is not portable: Studio serializes its own clients and checks disk immediately before rename, but an external write in the final check/rename gap can still race. Keep the overwritten base bytes in the revision store and report subsequent watcher conflicts; document this limit rather than claiming filesystem-wide transactions.

## 12. CLI and compatibility

```
simulatte studio MODEL[:NAME] [--project DIR] [--layout PATH]
    [--param NAME=VALUE ...] [--seed INT] [--horizon T | --arrivals N | --cutoff T]
    [--warmup T] [--safety-limit T] [--level full|kpi] [--kpi KEY ...]
    [--timeout SECONDS] [--port PORT] [--no-browser]
simulatte run MODEL[:NAME] [same execution options] [--output PATH] [--json]
simulatte run --reproduce REQUEST_ID [--project DIR] [--json]
simulatte worker --stdio
```

Studio auto-runs once after valid inspection/defaults, then on valid committed changes. Missing required params opens forms without running. CLI runs one attempt, waits for publication, prints request/attempt/outcome and artifact location. Default level full for Studio and single run; default seed 0. `--kpi` selects recorded/displayed keys, never removes behavioral accounting/default collectors; unknown keys fail at ready. No flags infer experiments. `--output` exports a committed trace to an explicit destination without overwriting an existing file (add no overwrite shortcut); failed/cancelled runs do not produce a success output. JSON mode writes exactly one bounded result envelope to stdout; human diagnostics/progress go to stderr. Exit 0 success/verified reproduction, 2 usage/validation, 1 execution/storage/protocol/reproduction mismatch, 130 user cancellation.

`run` and worker work on core installs and PyPy. `studio`/`view` give the existing optional-install message without `[studio]`; server targets CPython. Existing scripts need no decorator, snapshot or run store. Core import must not import execution/server machinery eagerly. Docs explain frozen Params, declared inputs/import discipline, finite-population integration, artifact side effects, snapshot limitations, local external dependencies, browser recovery and physical/presentation classification.

## 13. Verification and release gates

The plan maps each contract to tests. Required platform matrix: Linux and macOS CPython 3.11–3.15 (full version matrix on Linux, oldest/latest on macOS), PyPy 3.11 core/worker/snapshot/trace on Linux, Windows latest supported CPython local lifecycle/Job Object/server smoke as best-effort with explicit failures documented. No Windows remote promise. Browser matrix: current Chromium, Firefox and Playwright WebKit; actual Safari manual live edit/reload/cancel/export regression before release. Do not relabel WebKit as Safari.

Mandatory failure paths: malformed/oversized protocol; native print flood; import failure/hang/lazy editable escape; ready cancellation; infinite CPU loop; normal/grandchild cancellation and supervisor death; blocked stdout; delayed/lost ACK; full spool/disk; duplicate/out-of-order fragments; crash at every publication boundary; obsolete result after replacement; two-tab/external-file conflict; watcher rename/delete/missed event; invalid source/layout; authenticated but slow tab; cookie-only attacker; wrong Host/Origin; snapshot edit races; finite-population boundary/drain failure; result fingerprint mismatch.

Measure startup/inspection/ready/run/close wall time separately for short and long workloads on CPython/PyPy. Measure spool bytes/files/in-flight bytes, control latency and RSS under a stalled receiver. Acceptance: quotas never exceeded, normal cooperative cancel ≤2 s and forced cleanup within the 3 s escalation plus 2 s scheduling allowance, heartbeat gap <5 s while a consumer continues reading, provisional update visible within 2 s of a segment commit on an idle local machine. A disconnected/blocked transport is exempt from delivery latency, not from cleanup. Browser caches retain SP3 bounds and no frame-proportional React commits. These are targets requiring measurement, not claimed results.

Run existing full Python suite/99% branch gate, lint/format/typing, TS typecheck/tests, browser tests, docs and asset/wheel/sdist checks. Preserve old-reader verification and no-subscriber overhead gates; no silent budget adjustment. Release 0.16 and merge are subsequent maintainer actions, not authorized by this design document.

## 14. Primary documentation checked

Checked 2026-10-11; documentation supports API choices, not measured correctness. Implementation must verify the pinned dependency versions.

- [watchfiles watch/awatch](https://watchfiles.helpmanual.io/api/watch/): recursive change batches, explicit filtering/debounce, polling fallback and stop events. Use a custom filter and our own reconciliation.
- [Starlette websockets](https://starlette.dev/websockets/): pre-accept denial, JSON messages and disconnect lifecycle.
- [Uvicorn settings source](https://raw.githubusercontent.com/Kludex/uvicorn/main/docs/settings.md): explicit websocket backend, websocket queue/message controls and asyncio choice; do not assume optional websocket support from bare Uvicorn.
- [Python subprocess](https://docs.python.org/3/library/subprocess.html): sessions/process groups and pipe lifecycle; process groups alone do not supply parent-death containment.
- [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects): child association, kill-on-close and breakaway constraints. Actual suspended-spawn integration needs Windows tests.
- [Python site startup](https://docs.python.org/3/library/site.html): executable `.pth`/startup hooks and version-dependent `-S` behavior motivate isolated bootstrap.
- [Python audit hooks](https://docs.python.org/3/library/sys.html#sys.addaudithook): hooks are not a sandbox; import inventory is evidence with stated limits.
- [git ls-files](https://git-scm.com/docs/git-ls-files): cached membership and NUL-delimited paths; capture uses working bytes separately.
- [Python tarfile](https://docs.python.org/3/library/tarfile.html): normalized archive metadata and extraction hazards; SP4 validates/materializes entries itself.
- [Python sqlite3](https://docs.python.org/3/library/sqlite3.html): explicit transactions; filesystem publication requires the separate recovery protocol in A1.
